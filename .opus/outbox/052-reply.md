### Commit 2 — `b764d1f` `fix(deps): regenerate lockfile after fresh install`

Nuked `node_modules` and `package-lock.json` entirely, ran `npm install` from scratch (took ~2 min, 1037 packages). The fresh lockfile is functionally equivalent (84 lines added, 74 removed) but resolves the deduplication graph from a clean slate. Local `npm ci --no-audit --no-fund` again exit 0. Pushed. **CI install passed this time**, but typecheck failed:

```
src/app/api/head-commit/route.ts(1,33): error TS2307: Cannot find module '@/content/fallback-commit'
src/components/hero/hero.tsx(5,32): error TS2307: Cannot find module '@/content/build-metadata'
src/components/hero/hero.tsx(6,33): error TS2307: Cannot find module '@/content/fallback-commit'
tests/unit/head-commit-fallback.test.ts(3,33): error TS2307: Cannot find module '@/content/fallback-commit'
```

Cause: `src/content/build-metadata.ts` and `src/content/fallback-commit.ts` are auto-generated by `tsx scripts/collect-build-metadata.ts` in the `prebuild` npm hook (T002), and the directory is `.gitignore`d. Locally the files exist because I've run `npm run build` recently. CI runs `npm run typecheck` in isolation **before** any `npm run build`, so the generated files don't exist when `tsc --noEmit` reads the imports.

This was a latent bug in T002's pipeline — the generator only runs as `prebuild`, not as `pretypecheck`. T021 was also lucky to land green; CI must have had a stale checkout or run `build` before `typecheck`.

### Commit 3 — `3f9c6e2` `fix(deps): generate build metadata before typecheck for CI`

Added `"pretypecheck": "tsx scripts/collect-build-metadata.ts"` to `package.json` scripts. Now `npm run typecheck` will always regenerate the metadata first. Local verify → both pretypecheck and typecheck exit 0, metadata file regenerated. Pushed.

**CI is now green** on `3f9c6e2`. Run id `24118125911`, conclusion `success`, status `completed`.
